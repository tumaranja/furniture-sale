# furniture-sale

Public-domain (Unlicense) template for a one-page "sell your furniture to the next tenant" website. Derived from a real moving sale, anonymized.

## Rules

- `template.html` is the whole product, shipped with an empty data block (anything a seller leaves out stays empty): data in `<script id="sale-data">`, labels in `<script id="sale-labels">`, then CSS and a small vanilla JS renderer. The page itself needs no build step and no dependencies besides the Geist font.
- Keep the data options documented in the comment at the top of `template.html` (the "YOUR DATA" block) in sync with what the renderer reads.
- The photo layout lives in `arrangePhotos()` in `template.html`; RULES.md ("How the page works", Photos) describes its rules. Change both together.
- The example is `index.html`, generated by `python3 scripts/build-example.py` from `template.html` + `example/data.json`. Never edit `index.html` by hand; change the template or the example data, then rebuild.
- `docs/example.png` is a screenshot of the top of the example, shown in the README. Retake it when the top of the example changes (headless Chrome, 1100 px wide at 2x, cropped to 2200×1440 so the "Make your own" button is out of frame).
- Keep RULES.md ("How the page works") true to how the page behaves (layout, pricing logic, phone breakpoints at 720 px and 600 px).
- The example must stay anonymized: no real names, phone numbers or addresses (the example's phone and WhatsApp are fake 555 numbers).
- Commits are authored as `tumaranja <42451460+tumaranja@users.noreply.github.com>`.
- Three layers, each rule in one place: what the code does on its own goes in RULES.md "How the page works"; guidance for filling in fields goes in the top part of RULES.md; only must-keep rules (things that would break the page, invent content or leave the seller stuck) go in the README prompt. No dates; replace rules that change.
